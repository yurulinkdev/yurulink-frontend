# Frontend初期表示性能とページ境界

## URLとナビゲーション
- `/`：サイトの案内だけを表示する軽量ランディング。ロゴは `/` に移動する。
- `/welcome/`：同じ案内本文を保つ内部管理用ページ。canonicalを `/` に寄せ、個別の検索登録を抑止する。
- `/catalog/`：「すべてのコンテンツ」の検索・フィルタ・並び替え・ページ送りを提供する独立ページ。
- ランディング本文の最下部のリンクは `/catalog/` の「すべてのコンテンツ」1件とする。共通サイドバー・初回ガイドは保持する。
- 下層ページ・ランディングのカテゴリナビは `/catalog/?category=...` に遷移する。カタログ上でのカテゴリナビのみページ内更新する。
- `/` はクエリ文字列の有無に関係なくWelcome専用。旧 `/?category=...` を自動転送する処理は廃止。ユーザー操作なしに検索UIへ移行しない。検索条件を共有する場合は `/catalog/?...` を使う。

## 性能とデータ読み込み
- `/` と `/welcome/` は全件カードHTMLを取得しない。共通JSに `site.js` を含めず、ロゴ・ナビ・テーマ・初回訪問ガイドだけを動かす。
- `/catalog/` は検索UIを先に表示し、`/catalog-data/` からHugo生成HTMLを非同期取得。約4,800件はinertなtemplateへ保持し、DOMは20〜100件だけ描画する。
- `/catalog-data/` はnoindexの直接閲覧可能なHTML代替。データ分割と軽量索引は追加最適化候補であり、未実装を実装済みと誤認しない。
- CIのFCPはChromiumの参考値であり、実iPhoneのコールドロードを計測したことにはならない。計測はルート案内表示と検索ページの操作可能時刻を別々に評価する。

## 動作テスト
- Hugo Smoke: `/`・`/welcome/`・`/catalog/` の生成と、トップに検索・カタログが存在しないことを検証。
- Chromium: ロゴで案内へ戻る、案内の単一CTAで一覧へ移動、メニューからカテゴリ選択、検索・ソート・ページ送り、クエリ付きルートもWelcomeに留まりカタログを取得しないこと、noindexを検証する。
- `main`、Production、Backend、DNSはこのStaging変更の対象外。
